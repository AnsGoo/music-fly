## DLNA 投屏到电视报「播放器异常」修复

用户反馈：DLNA 投屏到电视时电视提示播放器异常 / 切到直链播放。排查后定位到投屏链路与后端已验证的 DLNA 兼容方案不一致，改动如下（只改代码 + 测试，未打包）：

- `lib/state/cast_audio_session.dart`：`AudioDlnaSession.loadMedia` 不再用 `DlnaSoapBuilder.buildSetAVTransportURI`——它硬编码 `<upnp:class>object.item.videoItem</upnp:class>`，音乐被电视交给视频管线。改为自建音频 DIDL（`object.item.audioItem.musicTrack`、albumArtURI、duration、正确的双重 XML 转义），并按 URL 是否 `dlna=true` 选 protocolInfo：转码流 `OP=00;CI=1`（与后端 didl.go 一致），MP3 直传 `OP=01;CI=0`。构造新增可选 `httpClient` 便于测试注入。
- `lib/data/musicfree_client.dart`：新增 `castStreamUrl()` / `castCoverUrl()`；非 MP3 走后端 DLNA 转码直链 `format=mp3&estimateContentLength=true&dlna=true`（后端 `serveTranscodedDLNA` 落临时文件 + `http.ServeContent`，给 Vewd 栈精确 Content-Length/Range/时长），MP3 保持原始直链。host 用 `_lanReachableBase()` 从 `allAddresses` 里挑纯 LAN 裸 IP（排除 `/app/` 网关、relay 域名、loopback），避免电视拿到需要 fnOS token/relay Cookie 的网关地址而 401。`_mediaUrl` 增加 `base` 覆盖参数。
- `lib/state/app_model.dart`：`_castToSession` 改用 `castStreamUrl`（`format == 'mp3'` 才直传，null/其它一律转码），并传封面 `imageUrl`。本地播放的 `needsTranscode` 逻辑未动。
- 测试：`test/cast_test.dart` 扩了 3 个用例（转码/直传/LAN 地址选择）；新增 `test/audio_dlna_session_test.dart`，用 `MockClient` 捕获 SOAP body 断言音频 metadata 与转义（flutter_test 会拦截真实 HTTP 返回 400，不能起本地 HttpServer）。
- 验证：`flutter analyze` 无问题；`flutter test` 全套 172 项通过（绕代理）。没有打包 DMG/APK。

注意：转码链路要求后端 ffmpeg 可用；首播会等后端先把整首歌转成 MP3，可能有启动延迟。电视端提示文案并非本项目产生（代码库中无此字符串），若现象仍在需确认提示来自哪一端。

## DLNA 电视显示「未知歌手 / 未知专辑 / 无歌词」修复（同日第二轮）

用户反馈：能播了，但电视显示未知歌手、未知专辑，也没有歌词。

- 根因 1：自建 DIDL 只有 `dc:title` / `upnp:class` / albumArtURI / res，没带 `dc:creator`、`upnp:artist`、`upnp:album`（后端 `didl.go` 一直有）。电视只能显示 unknown。
- 根因 2：App 端歌词绑的是 `player.state`，投屏时本地播放器是暂停的旧歌，位置不动 → 歌词不滚动、进度条也不动。
- UPnP AV / DLNA **没有标准歌词属性**；audioItem 只有 `dc:description`、`dc:longDescription` 等自由文本属性。所以电视端歌词只能尽力而为，App 端才是可靠同步视图。

改动：
- `lib/state/cast_audio_session.dart`：新增 `CastAudioMetadata`、`buildCastAudioMetadata()`（净化 XML 非法控制字符 + 截断：artist/album 200、歌词 2000）、顶层 `loadCastAudio()` helper；`AudioDlnaSession` 拆出 `loadAudio(media, metadata:)`；DIDL 补 `dc:creator` / `upnp:artist role="Performer"` / `upnp:album` / 第二个 `albumArtURI dlna:profileID="JPEG_TN"` / `dc:description`(纯文本歌词) / `dc:longDescription`(LRC 原文)，并声明 `xmlns:dlna`；`_escapeXml` 过滤 XML 1.0 非法字符。
- `lib/state/app_model.dart`：`_castToSession` 在 SetAVTransportURI **之前**先取歌词（一次 DIDL 不能后补），用 `retryable: false` + 1s 超时，失败照常投；新增私有 `_plainLyrics()`。新增稳定的 `ValueNotifier<PlaybackState> playback`：本地时镜像 `player.state`，投屏时由 `session.positionStream` + `stateStream` 驱动（`_mirrorLocalPlayback` / `_publishCastPlayback`），断开时还原；`connectCast` 订阅 `_castPositionSub`，dispose 里清理。
- `lib/data/musicfree_client.dart`：`_get` 拆出 `_getWith(..., retryable:)`；`structuredLyrics(trackId, {retryable = true})`，投屏传 false，避免可选歌词请求把全局重登/地址探测拖进起播链路。
- UI：`now_playing.dart`、`player_bar.dart`、`lyrics_view.dart`、`detail_view.dart`、`home_view.dart`、`browse_view.dart` 统一改用 `model.playback`（含唱片旋转监听），投屏时进度、歌词、当前曲目高亮跟随电视。
- 测试：新增 4 个用例（DIDL 元数据/净化、AppModel 拼装、playback 跟随投屏），`now_playing_test.dart` / `queue_sheet_test.dart` 的 `_OfflineClient` override 补 `retryable` 参数；队列推进测试改为轮询等待（投屏前多了歌词请求，一次 microtask 不够）。
- 验证：`flutter analyze` 无问题、`flutter test` 全套 **176 项通过**，未打包。

遗留：歌词在电视端是否显示取决于接收端是否读 `dc:description` / ID3 USLT；DLNA 没有同步歌词标准。若电视仍不显示，只能改后端把 USLT 歌词写进转码 MP3 或提供 LRC sidecar 直链。

用户反馈：投屏遥控面板里橙色「⏸ 暂停」胶囊太大，要用图标；同时报 `LateInitializationError: Field '_playback@...' has not been initialized.`

- `lib/ui/cast_sheet.dart` 把控制行抽成公开 `CastTransportControls`（纯参数、无 AppModel 依赖），便于独立 widget 测试；新增 `test/cast_controls_test.dart` 3 例（无文字、34dp 与上一首/下一首同尺寸、点击与图标切换）。
- **热重载报错根因**：上一轮把 `_player` 换成 `late final ValueNotifier<PlaybackState> _playback` 并在 `initState` 里赋值，Hot Reload 保留 State 但不重跑 initState → 读未初始化字段。修复：`player_bar.dart` / `now_playing.dart` 改成可空 `_playback?`，`didChangeDependencies` + `reassemble` 里 `_bindPlayback(context.read<AppModel>().playback)` 重绑（identical 检查避免重复 addListener），dispose 与 `_syncSpin`/`_followPlayback` 一律空安全。
- 测试踩坑：在 `cast_test.dart`（大量真实异步 + AppModel 探测定时器）里混 `testWidgets` 会永久挂起并被 SIGTERM（FakeAsync 时钟不推进 + runAsync 也救不回）。改成独立的纯控件 widget 测试文件，不要在含真实 timer 的测试文件里加 `testWidgets`。

## FNID 登录强制输入 Music Free 账号（同日第四轮）

用户要求：FNID 连接完成后必须输入 Music Free 账号才能登录，防止网关免密直接登录、无法更改默认登录的用户。

- 根因两处：`prepareFnConnect()` 探测成功后调 `_tryAutoGatewayLogin()`，用 `gatewayLogin()` 免密直接进首页；即便走到第二步，`loginFnPrepared()` 的网关分支也先 `gatewayLogin()`，成功就忽略用户填的账号密码 → 永远登录到后端 NAS 绑定里的默认账号。
- `lib/data/musicfree_client.dart`：新增 `loginFnAddress(url, user, pass)`（空凭据直接拒绝；`/app/` 网关走 `gatewayBind(anonymous: true)`，每次重绑并签发该账号；**绑定端点任何失败都 fallback 到同一地址的普通 `login`**，因为「网关登录未启用」的 404 JSON 会被包装成 `AuthException`，只按类型区分会把用户卡在登录页；直连/中继普通 `login`）。`gatewayBind()` 加 `anonymous` 参数，避免旧 JWT 随重绑请求发出。
- `lib/state/app_model.dart`：删除 `_tryAutoGatewayLogin()` 与 `fnGatewayLoginAvailable`；`loginFnPrepared()` 强制非空凭据 + 调用 `loginFnAddress()`；新增 `_lastFnConnect` / `preferFnConnectTab`（restoreSession / login / `_completeFnLogin` 维护，logout 不清）和 `@visibleForTesting setFnProbeForTest()`。`gatewayLogin()` 仅保留在 `_reloginSilently()` 做 JWT 过期续期。
- `lib/ui/login_page.dart`：第二步提示统一为「第二步 · 输入 Music Free 账号密码，可更换登录账号」，去掉「网关已校验身份，点登录即可进入」；重登/登出后按 `preferFnConnectTab` 自动回到 FNID 页签。
- 测试：新增 `test/fn_login_credentials_test.dart`（9 例：网关 bind / 直连中继 login / 空凭据不发请求 / 旧后端 404 纯文本 fallback / 网关未启用 404 JSON fallback / 密码错保留后端消息 / AppModel 拒绝空凭据 / 以 alice 登录且无 gateway-login / 恢复 FNID 会话保留页签偏好）与 `test/fn_login_page_test.dart`（2 例 widget）。
- 验证：`flutter analyze` 无问题、`flutter test` 全套 **190 项通过**，未打包。
- 副作用提醒：网关链路每次登录都会更新后端的 NAS→账号绑定，其它通过统一网关免密进入的端也会跟着换成该账号；多 NAS 用户共用同一 Music Free 账号时可能被后端 `saveNasBinding` 互相解绑。
