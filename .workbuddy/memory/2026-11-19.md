# 2026-11-19

## 修（第三次）：锁屏元数据冻死——昨天的修复自己埋的雷（Promise 不能存 AppStorage）

- 现象：与 11-18 相同——App 内切歌，锁屏元数据不变。
- 排障：昨天起的后台 `nohup hilog` 仍在跑（/data/local/tmp/mf_live2.log 已 2.6GB），完整回放全天日志：
  - pid 20476（昨天 15:53 装的新包进程）从早上到 14:30:56，rev=31~87 全部 `SetAVMetadata successfully`；
  - **14:30:56.608 起（用户复现快速切歌、出现第二个播放器实例时），每次推送报 `createSession failed: code=undefined, message=Then: thisValue is not promise!`**（昨天加的 mfSessionErrorDetail 首立功），且无任何 `createAVSession attempt N failed`——说明 mfCreateSharedSession 根本没执行，缓存命中即炸；
  - hidumper：会话还在系统里且是 topsession；`-show_metadata` 全空。
- 根因：**AppStorage 不能存 Promise**。AppStorage 是 ArkUI 可观察存储，对象存入后 `get` 取回被观测包装，不再是原生 Promise 实例。进程启动后第一个实例走 `mfSharedSession` 的创建路径直接拿到真 pending（没经过 AppStorage）→ 全天正常；**第二个实例**（切歌重建播放器）→ 从 AppStorage 命中「缓存」→ `await` 非 Promise 抛 `Then: thisValue is not promise!` → this.session 永远 undefined → 每次推送触发 createSession 失败。昨天（11-18）把 AppStorage 当跨模块全局是错的——那次的真实救星其实是「拒绝态不再缓存 + 主动重建」，AppStorage 那半纯属多余还埋雷。
- 修复（MediaAvPlayer.ets）：
  1. `mfSharedSession` 弃用 AppStorage，只用模块级静态 `mfSessionPromise`（本文件内自产自销，无跨模块读取，静态安全；JS 堆与进程同生命周期，冻结/解冻不丢）；`instanceof Promise` 校验缓存，变质即丢弃重建（防御）。
  2. `mfAwaitWithTimeout` 加守卫：p 不是 Promise（如对已销毁会话 destroy() 返回 undefined）时 reject 明确错误，不再让 `p.then` 抛运行时错。
  3. 删除 MF_AV_SESSION_KEY 常量；`mfInvalidateSharedSession` 去掉 AppStorage.delete。
- 经验：**AppStorage 只放简单类型和需要跨模块共享的普通对象快照**（MF_ACTIVE_PLAYER_KEY/MF_AV_METADATA_KEY 保留是合理的——纯数据对象，且确实跨 MainMethodCallHandler 读取）；Promise、带原生绑定的对象（AVSession）一律模块级静态。
- 日志考古技巧：长后台 hilog 落盘文件直接 grep 关键 TAG 能完整回放（hilog 缓冲区几分钟就被 speeddone 刷光，靠它抓不到跨天的现场）。
