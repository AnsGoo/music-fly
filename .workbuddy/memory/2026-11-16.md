# 2026-11-16

## 修：鸿蒙锁屏/播控中心出现「封面是这首、歌名歌手是另一首」的错配

- 现象：鸿蒙手机播放 A 时，面板封面是 A、歌名和歌手却是 B；用户无法稳定复现（时序问题）。
- 定位：App 内 UI 不可能错配（`now_playing`/`player_bar` 的封面与文案都取自同一个 `PlaybackState`），问题只在鸿蒙 AVSession 元数据链路——歌名/歌手与封面是分两次下发的。
- 根因 1（原生 `MediaAvPlayer.ets` 的 `decodeArtwork`）：封面 `createPixelMap` 之后只校验了一次 `artworkToken`，而中间还 `await this.releaseArtwork()`；这段 await 期间若切歌，旧封面会继续落到**新歌的全局快照**上（快照 title 已是新歌、artwork 是旧歌），锁屏于是显示「新歌名 + 旧封面」或反之。窗口极短，因此无法稳定复现。
- 修复 1：新增 `MfAvMetadata.artworkAssetId`（封面归属曲目）；新增 `artworkStillWanted(token, assetId)` 三重复验（活跃实例 + token 未变 + 快照 assetId 未变），在**每次 await 之后**都校验；`setAVMetadata` 只在 `artworkAssetId === assetId` 时才用 PixelMap，否则退回 artUri，别人的图绝不借用；`releaseArtwork` 同时清归属。
- 修复 2（顺手）：`setSessionMetadata` 只在**换曲**时清封面（`sameTrack` 判定），同曲重推不再把已解好的图清掉（避免闪回可能取不到的 artUri）。
- 根因 2（Dart `player.dart`）：`_systemMetadataConfirmed` 的确认补推在「播放刚开始」就触发，那时封面往往还没下载完，等于把一份不带封面的半成品又写一遍，面板可能停在半新半旧状态。
- 修复 2：新增 `_playbackStarted` / `_coverResolved` 两个标志，`_maybeConfirmSystemMetadata()` 只在「已出声 + 封面定局」后补推一次，推出去的必然是一份自洽的完整数据（含 artwork 字节）。
- 验证：`flutter analyze` 无 issue；`flutter test` 210/210 通过（无 Dart 接口变更，ArkTS 侧需用户在 DevEco 里重新签一次 App 才能验证）。
- 用户确认：错配就发生在**鸿蒙锁屏**，方向正确。
- 修复 3（用户确认锁屏后的补强，`player.dart`）：需要鉴权的封面 URL（`fnRelayHeadersFor(url) != null`，即飞牛网关 `/app/` 与 relay 域名）不再作为 `artUri` 交给系统去取——系统没有那些头，只会 401，而锁屏卡片取不到新图时会把上一首的封面留在原位，表现同样是「封面/歌名不是同一首」。这类链接现在先推空串（合法兜底），真正的图由 App 下载字节后补 PixelMap。
